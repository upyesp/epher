IDE Extensions

Write epher in your editor: a language server checks every statement as you type, shows each answer next to its line, and completes names from the catalog.

One server, every editor

Every extension shares one program, epher-lsp: a small language server with the whole epher engine compiled in. The extension is a thin shell: on first use it downloads the server for your platform from the releases page and caches it. Everything runs on your machine; nothing is sent anywhere.

What the editor gets

  • Live diagnostics: Syntax errors point at the exact token, and evaluation errors carry the same message the calculator shows.
  • Answers inline: Each statement's result renders next to its line: `x = 40 + 2` shows `= 42`.
  • Hover signatures: Hover a name for its canonical signature and description; your own constants show their current values.
  • Completion and snippets: Catalog names, your own definitions, keywords, and snippets for the common statement shapes.
  • Unit-aware coloring: Semantic tokens color unit suffixes by meaning: the `m` in `2 m` is a unit, not a variable.

VS Code

Download `epher-vscode.vsix` from the releases page, then install it: Extensions view, the ⋯ menu, Install from VSIX.

Download epher-vscode.vsix from the releases page

On first use the extension downloads the server for your platform (Windows x86_64, Linux x86_64 and ARM64, or macOS Apple silicon) and needs the network once; after that, everything is local. Open a `.epher` file and the answers appear.

JetBrains IDEs

Download `epher-jetbrains.zip` from the releases page and install it from disk: Settings, Plugins, the gear menu, Install Plugin from Disk. Works in IntelliJ IDEA, PyCharm, WebStorm, GoLand, and the rest of the family, 2024.2 or newer. On first use it downloads the server for your platform; after that, everything is local.

Zed

Install it as a dev extension: in Zed, run the `zed: install dev extension` command and pick the `clients/zed` folder of the repository. Zed compiles the extension itself, which needs Rust installed. For coloring, flip one setting: `languages.epher.semantic_tokens = full`.

Neovim and Vim

Ready-made config files live in the repository under `clients/vim` and `clients/nvim`: filetype detection, syntax, and the LSP wiring around the same release binary. Point your runtimepath at the folder and call `require("epher").setup()` on Neovim 0.11 or newer.

Sublime Text

A package folder under `clients/sublime`: the shared grammar in Sublime's own form, plus the client definition for the popular LSP package.

Visual Studio

Planned last: Visual Studio speaks the same protocol through its SDK, and the extension follows once the other editors have proven the server.

All of this lives in the repository under clients/.

Any LSP client

The server speaks the Language Server Protocol over stdio, so any LSP client works. Download the binary for your platform from the releases page, uncompress it, and point your editor's client at it:

Platform Release asset After extracting
Windows (x86_64) epher-lsp-windows-x86_64.zip epher-lsp.exe
macOS (Apple silicon) epher-lsp-macos-aarch64.gz epher-lsp
Linux (x86_64) epher-lsp-linux-x86_64.gz epher-lsp
Linux (ARM64) epher-lsp-linux-aarch64.gz epher-lsp

Check the install with `epher-lsp --version`.

Everything is on the releases page.
