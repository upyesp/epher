Accessibility

epher should work for everyone. This page describes how this website, the web app, and the command-line and terminal programs support assistive technology, what the project holds them to, and what to do when they fall short.

In brief

The project is committed to making epher accessible for everyone. While the project tests against standard web guidelines, nothing replaces real human experience. If you run into any difficulties using epher or have ideas for improvement, please open an issue. The project will address it as a priority.

What the project holds itself to

epher targets WCAG 2.2 Level AA, the Web Content Accessibility Guidelines. Every change to this site and the web app is tested against that bar before it ships: an automated axe-core scan with zero violations required runs on every deploy, a deeper pass covers every interface language, text-spacing overrides, Windows High Contrast, and touch-target sizes, and the web app is hand-tested with a real screen reader. This is a self-evaluation, documented in the open repository; no outside auditor is involved.

Known limitations

  • On macOS, Chromium-based browsers do not deliver live-region announcements to VoiceOver, so a new result may not be spoken until you move focus; Safari delivers them.
  • Graphs are visual. Each plot is named in text: the expression appears as a caption and inside the exported SVG, but the shape of a curve or surface is not described in detail.
  • In the terminal, screen-reader support depends on your terminal emulator. The terminal app stays fully keyboard-operable and shows a text caption above plots.

Feedback

If anything here or in the apps is hard or impossible to use with your assistive technology, please open an issue on GitHub. Include your browser or terminal and the assistive technology you use; accessibility problems are treated as bugs.
